1 · District weight — open ruling: the default was flipped log → derived, unseen

derived — the current default modules 81.5% · test 8.5% · src 6.3% · bin 2.0% · lib 0.8% · scripts 0.8% log — the previous default modules 40.3% · test 20.7% · src 18.3% · bin 9.2% · lib 5.7% · scripts 5.7% sqrt modules 69.2% · test 12.5% · src 10.0% · bin 4.2% · lib 2.1% · scripts 2.1% linear — the original modules 94.4% · test 3.1% · src 2.0% · bin 0.3% · lib 0.1% · scripts 0.1%

Read this before ruling. The log default was chosen (2026-08-30) to stop one district eating the canvas — it cut the largest share 71.3% → 40.9% on the previous repo. The new derived default hands the largest district 81.5% here: more concentrated than sqrt, and much more than the log it replaced. On this repo, deriving the exponent from the distribution undoes the correction the earlier ruling made. That may be right — a monorepo whose modules genuinely are 4/5 of the code arguably should look like it — but it is the opposite of what the previous ruling optimized for, and nobody has looked at it.

The floor is binding under derived: lib and scripts both land at exactly 8.00 deep on a 1000-wide canvas — the 0.008 district-legibility floor. That is the known geometry mismatch: the floor was derived for a square district proxy, but districts lay out as full-width strips, so hitting the floor buys a 1000×8 sliver rather than a legible patch. Under linear the same two districts fall to 0.86 deep — below the floor entirely. All four compile from the same graph; --district-weight=linear|sqrt|log still reproduces pre-ruling cities byte-for-byte.
